## 1. 时间语义

每个原始字段至少声明：

- `event_time`：经济事件实际发生时间；
- `published_at`：交易者首次可公开获得的时间；
- `ingested_at`：数据进入研究系统的时间；
- `available_at`：经过清洗、供应商处理或授权后可供策略使用的时间；
- `decision_time`：因子形成和下单决策时间；
- `earliest_fill_time`：在市场制度和执行假设下最早可成交时间。

硬规则：

```text
available_at <= decision_time < earliest_fill_time
```

若某字段只能提供日期而没有时分秒，采用保守滞后，不得假定开盘前已知。

不要把数据库中的“报告期”当作信息可得时间。财报、业绩预告、快报、公告、分析师预测和监管问询均以实际公开时间为准。

## 2. 历史股票池

按每个历史时点重建：

- 上交所、深交所、北交所及具体板块范围；
- 当日上市、退市、暂停上市、终止上市和代码变化；
- 指数或策略母样本的历史成分；
- ST/*ST/风险警示状态；
- 上市天数、价格、流通市值和流动性过滤；
- 策略是否允许新股、次新股、退市整理期和特殊证券。

禁止：

- 用今天仍上市的股票回测过去；
- 用当前指数成分替代历史成分；
- 事后删除破产、长期停牌或数据不完整的失败样本；
- 先按未来流动性、未来市值或完整历史长度筛选证券。

将“研究母样本”和“真实可交易样本”分别保存。前者用于识别偏差，后者用于组合执行。

## 3. 行情与公司行动

明确：

- 原始价、前复权、后复权或总回报口径；
- 现金分红、送转、配股、拆并股和除权除息处理；
- OHLC、成交量、成交额、盘口和逐笔数据的时区、频率与撮合语义；
- 集合竞价、连续竞价、收盘集合竞价和盘后数据的边界；
- 跨日收益是否包含分红；
- 停牌日、无成交日和异常成交的处理。

研究因子与回测收益可以使用不同价格序列，但必须能解释二者的映射。例如，复权序列用于连续收益计算，订单仿真使用当时真实价格和交易单位。

## 4. 基本面与事件数据

基本面字段记录：

- 报告期；
- 首次公告时间；
- 更正、补充或重述版本；
- 合并报表口径；
- 单位、币种和会计准则；
- 截止决策时间可见的最新版本。

事件与文本字段记录：

- 原始文档 URL/ID 和哈希；
- 发布主体和可信度；
- 首次发布时间及后续修改时间；
- 实体映射版本；
- NLP 模型、提示、词典和特征版本；
- 是否包含盘中、盘后或未来摘要信息。

对仅有当前最终值、无法重建历史版本的数据，标记 `not_point_in_time`。它可以用于探索，不能直接支持生产准入。

## 5. 可交易性

按订单时点和成交时点建立 `tradability_mask`，至少考虑：

- 停牌和无报价；
- 涨跌停以及是否存在真实可成交量；
- ST/风险警示限制；
- T+1 对当日买入后卖出的限制；
- 最小交易单位和取整；
- 成交量、成交额、ADV 和参与率；
- 板块或证券的交易制度差异；
- 佣金、税费、过户费、点差、冲击和延迟；
- 融资融券标的、可借数量、借券成本和召回风险；
- 组合层现金、杠杆、集中度和行业约束。

不要把收盘信号按同一收盘价成交，除非能证明信号在该成交窗口前已冻结且成交模型允许。

交易规则、费率和板块制度可能变化。涉及当前数值时，查询交易所、券商或监管机构的最新正式资料，并在报告中记录生效日期。

## 6. 数据审计

### Time-travel test

随机选择多个历史截止时间，只提供截止时间前可见的数据重新计算因子。结果必须与全库在该时点的输出一致。

### Universe replay

随机抽取历史日期，核对证券状态、指数成分、ST、停牌、上市/退市和公司行动。

### Label-boundary test

确认训练样本的标签区间没有跨入验证或测试区间。重叠时执行 purge；必要时按信息重叠设置 embargo。

### Revision audit

对基本面和事件数据比较首次版本与最终版本。量化因子对修订敏感时，报告这种差异。

### Execution replay

从信号时间沿订单、成交、持仓和收益链回放，验证涨跌停、停牌、T+1、取整和费用。
