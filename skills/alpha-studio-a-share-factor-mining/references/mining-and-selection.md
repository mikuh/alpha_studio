# 因子挖掘、筛选与组合搜索

本文件规定“主动寻找好因子”的默认方法。目标不是把所有候选都证明有效，而是在明确预算内，找出最值得继续交易验证的少数单因子和组合，并完整保留失败证据。

## 1. 搜索对象

一个候选不仅是公式，还包括：

```text
候选 = 因子族 + 输入字段 + 参数/窗口 + 方向 + 可得时点
      + 股票池 + 预处理 + 预测期限 + 调仓/持有 + 成本口径
```

任何一项变化都形成新 trial。不要在结果出来后悄悄改名覆盖。

## 2. 候选生成顺序

默认按以下顺序扩展：

1. 用户提供或有经济逻辑的种子因子；
2. 预先声明的少量相邻窗口；
3. 同一字段的合理方向假设；
4. 价量、价值、质量、规模、波动和流动性中可由现有字段计算的候选；
5. 去冗余后才做组合。

禁止默认做无限公式枚举、遗传编程或在 final holdout 上搜索。若候选很多，先用 `max_factor_candidates` 和 `max_combination_candidates` 截断，并在 trial ledger 记录被预算排除的定义。

## 3. 单因子筛选

先应用硬门槛，再做相对排序。硬门槛至少包含：

- 验证期有效 RankIC 天数；
- 覆盖率；
- 预期方向；
- discovery 与 validation 是否同向；
- 用户声明的成本后表现底线。

通过门槛的候选再按下列证据的百分位加权：

- 验证期 RankIC；
- RankIC IR 与正向比例；
- 成本后组合 Sharpe；
- 最大回撤；
- 换手；
- discovery 到 validation 的衰减。

百分位评分只用于确定研究优先级，不是显著性证明。权重必须写在配置里，不得看到结果后反复调整。

## 4. 去冗余

按选择分数从高到低遍历候选，计算验证期逐日横截面 Spearman 相关。若某候选与已保留因子的相关绝对值超过 `max_pair_correlation`，标记 `redundant_with` 并跳过。

因子值相关只是第一层。正式研究还应比较：

- IC 序列相关；
- Top/Bottom 持仓重合；
- 交易方向和换手相关；
- 对行业、市值、beta、流动性和波动的暴露；
- 对已有组合的残差 IC 与净收益增量。

## 5. 组合搜索

只从去冗余后的 pool 生成组合。内置基线支持：

- `equal`：等权，作为首选可解释基线；
- `validation_ic`：按正的验证期 RankIC 归一化加权。

权重只使用 discovery/validation。组合大小和数量由配置限定。组合必须按与单因子完全相同的股票池、时点、持有期和成本重新评测；不能把单因子指标机械相加。

优先保留满足以下条件的简单组合：

- 验证期多指标得分较高；
- 成本后净表现没有被换手吞噬；
- 相比最强成分有增量或显著降低回撤；
- 成分经济逻辑不过度重复；
- 相邻窗口和不同市场阶段不过分脆弱。

默认 `require_combination_increment=true`：若组合在验证期 RankIC、成本后净 Sharpe和最大回撤三个维度均未优于各自最强成分，则不进入 Top 组合，并明确建议保留简单因子。

## 6. 最终留出集协议

严格顺序为：

```text
discovery 探索
→ validation 选择、去冗余和定权
→ 冻结 Top 单因子/组合
→ final holdout 只评测冻结名单
→ 不根据 holdout 重新排序或调权
```

内置挖掘器会遮蔽未入围候选的 final holdout 前瞻收益，并在 `trial_ledger.csv` 标记哪些候选看过 holdout。

## 7. 最终交付

必须直接回答：

- 哪些单因子最好，公式和方向是什么；
- 哪些组合最好，成分与权重是什么；
- 使用什么调仓、持有和成本假设；
- 验证期和冻结留出集证据如何；
- 哪些候选因覆盖、方向、成本或冗余被淘汰；
- 何种条件下应停用；
- 距离 shadow/实盘还缺什么。

若没有候选通过门槛，正确结论是“本轮未找到合格因子”，而不是降低门槛制造推荐。
