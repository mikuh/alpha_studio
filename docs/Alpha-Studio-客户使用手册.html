操作约定

路径使用“›”分隔

例如 设置 › 账户与授权 › 设备管理。按钮名使用粗体；风险、数据时点和人工复核要求用提示框标出。

AI 输出不是投资承诺

软件用于研究辅助，不替代投资决策、合规审查或真实交易授权；任何证券结论均须独立核验。

INSTALLATION

安装、更新与首次启动

04

安装步骤

  1. 确认安装包来自正式交付渠道，并核对版本说明。
  2. 打开安装包，将 Alpha Studio 安装到系统应用目录。
  3. 首次启动时，如系统提示来自已识别开发者，按企业 IT 规范放行。
  4. 不要使用来源不明的破解包、共享授权或第三方修改版。
升级前必须备份：应用升级通常保留本地数据，但重要项目、持仓、研究资料和会话历史仍应先完成备份。

建议运行环境

项目建议
设备受支持的 macOS 客户端设备
网络首次激活、授权续租、模型与行情服务需联网
磁盘为项目资料、附件、日志及备份预留空间
权限按需允许访问所选项目目录；不要授予无关目录

短期离线

最近一次在线校验成功后的授权可在有效期内继续使用。超过五天通常需要重新联网校验；具体以客户授权策略为准。

DATA BOUNDARY

本地数据、模型传输与账号安全

06
LOCAL本机资料项目目录、持仓、研究资料、会话历史与设置默认保存在当前设备。
→
USER ACTION发起模型调用只有在你主动发送任务时，所需对话、附件和上下文才会进入请求。
→
PROVIDER模型服务方请求发送给所选模型服务方，并按其协议处理或保留。

发送前删除

  • 不必要的个人信息
  • 证券账户及交易凭证
  • 商业秘密或未公开信息
  • 无权向外部提供的材料

账号登录原则

  • 使用本人或机构合规持有的账号
  • 通过服务方官方页面登录
  • 异常时退出并重新登录
  • 不把验证码发给服务人员

最小权限原则

  • 项目使用独立工作目录
  • 仅挂载任务需要的资料
  • 执行敏感命令前检查批准方式
  • 定期撤销离职或遗失设备
重要：Alpha Studio 业务服务端不以项目资料库的方式保存上述本地内容；但模型服务方的数据处理规则与 Alpha Studio 不同，请按其协议及本机构制度执行。

PROJECTS & FOLDERS

创建研究主题并绑定资料目录

08
01新建主题在左侧“研究主题”标题旁点击“+”。
02清晰命名使用“行业/公司 + 研究目标 + 日期”。
03设置目录在主题菜单中选择“设置资料目录”。
04确认备份将目录纳入机构或个人备份方案。

推荐目录结构

目录内容建议
00_研究计划问题定义、假设、数据需求先写研究边界
01_原始资料公告、研报、表格、会议纪要保留来源和日期
02_分析过程中间表、脚本、笔记不要覆盖原始数据
03_交付成果最终报告、图表、归档包区分草稿与发布版

主题管理操作

  • 在主题中新建对话
  • 置顶高优先级研究
  • 按名称或最近活动排序
  • 重命名并保持统一命名规范
  • 任务完成后归档，而非直接删除
目录不是云盘：绑定只让软件访问本机路径，不会自动生成远程备份。
建议：一个研究主题对应一个独立目录，减少不同客户、项目或权限边界之间的资料串用。

CONVERSATION

新建对话并提出高质量问题

09

发起任务

  1. 点击左侧新对话或快捷键 ⌘N。
  2. 确认当前研究主题和资料目录。
  3. 选择技能、模型、推理强度与批准方式。
  4. 写清目标、范围、数据时点、输出形式和限制条件。
  5. 发送后观察工具调用、批准请求和最终交付。
可复用提问模板

请在【数据时点】基础上，对【对象】完成【任务】，优先使用【资料/来源】，输出【格式】，并明确区分事实、推断与待核验项。

示例：基于 2026-08-04 收盘数据，复盘某行业的成交、主线地位和催化，输出结论、证据、证伪条件与下一交易日观察清单。
追加要求：所有关键数字标明单位和日期；若缺少数据，不得编造，列出补数清单。

先给结论

要求“结论—依据—风险—行动”结构，便于快速决策。

锁定时点

行情、估值、政策与财务数据必须注明截至日期。

要求反证

让模型给出失效条件，避免只收集支持性证据。

COMPOSER CONTROLS

附件、目录、模型与批准方式

10
1添加上下文：附加文件、图片或其他任务资料。

DAILY ROUTINE

盘前—盘中—盘后标准工作流

12
08:30 前盘前报告隔夜市场、政策与新闻映射；识别主题、催化、标的和证伪条件。
→
09:25–11:30盘中监控检查竞价、量价、资金和触发条件；记录数据缺口，不追认未知事实。
→
13:00–15:00持续跟踪更新触发、升级和失效状态；必要时召集联合研判与风险检查。
→
收盘后复盘与校准对照实际行情，复盘判断、归因偏差、更新台账和下一日清单。

每次都要记录

  • 研究对象与数据时点
  • 事实、推断与建议
  • 支持证据与反证
  • 触发、失效与复盘节点

联合研判时

  • 明确参与角色与分工
  • 保留分歧，不强行一致
  • 风险结论独立呈现
  • 最终形成行动优先级

归档前检查

  • 关键数字有单位与日期
  • 来源链接或文件可追溯
  • 结论无确定性收益承诺
  • 最终文件单独落盘

DAILY DECISION

从报告到跟踪验证

18

→
JOINT REVIEW联合研判主线、风险与基金经理副官分别给出判断、分歧和行动倾向。

每日决策标签

标签用途
今日摘要汇总主题、建议、风险与待办
主题选择主题与股票池，查看层级和条件
联合研判多角色研究，保留分歧与数据缺口
建议卡记录倾向、优先级、触发与失效条件
跟踪验证进入今日作战、台账、复盘、回测和校准

验证纪律

  • 历史报告不使用当前行情补算盘中触发
  • 缺数据时标记“待补数据”，不得猜测
  • 人工覆盖触发状态时记录理由和时间
  • 回测使用可获得的历史数据，避免未来函数
  • 小样本校准只做诊断，不做过度结论
“建议卡”属于研究记录，不等同于正式投资指令、合规批准或真实交易委托。

支持的常见成果

MarkdownHTMLPDF表格图像代码/脚本

HTML 可在内置浏览器预览；PDF 可在阅读器中查看。预览不代表最终发布审核已通过。

最终交付检查

  • 文件名包含对象、用途、日期和版本
  • 最终版与草稿分离，避免覆盖原始材料
  • 关键结论可回溯到来源或证据 ID
  • 报告中注明数据时点、单位和假设
  • 删除不应进入交付包的临时文件与凭证
  • 在独立设备或阅读器中完成一次打开测试
不要归档凭证：API Key、密码、Cookie、Token、恢复码和本地授权文件不得放入研究成果包。
推荐：将最终结论另存为独立文件，不要把研究计划、合规备注或某一位协作者的草稿当作最终交付。

FAQ

常见问题

25

Q1 · 软件会把我的项目全部上传到云端吗？

不会自动整体上传。项目和会话默认在本机；你主动发起模型调用时，完成请求所需的上下文会发送给所选模型服务方。

Q2 · 可以把模型账号密码交给服务人员配置吗？

不可以。使用官方页面登录；不要提供密码、验证码、Cookie、Token、恢复码或本地授权文件。

Q3 · 模拟交易会提交到券商吗？

不会。工作台交易用于模拟研究和复盘，不代表实盘连接或真实委托。

Q4 · 聚宽数据不可用还能研究吗？

可以使用本地资料、公开来源和其他已授权能力；但依赖聚宽字段的功能会提示缺失或权限不足。

Q5 · 升级会丢失本地数据吗？

常规升级通常保留数据，但任何升级前都应备份。卸载也不一定删除所有本地文件。

Q6 · 设备丢失怎么办？

立即联系管理员撤销对应设备，同时退出模型服务账号并按机构流程处理本地数据风险。

Q7 · 为什么同一任务费用不同？

模型、输入上下文、附件规模、输出长度和推理强度都会影响 Token 与费用。

Q8 · AI 的建议可以直接写进投委会结论吗？

需先核验来源、时点、假设、反证和合规口径，再由有权限人员复核并承担最终责任。
