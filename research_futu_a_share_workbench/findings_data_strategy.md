# A 股投研工作台数据源策略（东财 / JQData / 富途 OpenD）

> 结论先行：不要把“富途公开接口”理解成可匿名直连、可自由转售的数据 API。富途 OpenAPI 的标准形态是用户本机运行 OpenD、登录富途账户并按账户行情权限取数；它适合作为**可选的用户授权实时源**，不适合作为产品后端统一向所有用户分发行情的默认源。建议采用“富途 OpenD（授权实时）→ 现有东方财富网页接口（公开降级）→ 本地缓存/样例（离线兜底）”的盘中链路，以及“JQData（日线、财务、宏观、因子）→ 本地缓存”的研究链路。

## 1. 当前项目已有能力

- `src/eastmoney.ts` 与 `src-tauri/src/lib.rs` 已接入东方财富 `push2delay.eastmoney.com` / `push2.eastmoney.com` 网页行情接口，包含 A 股批量快照、全市场分页与分笔；字段已映射价格、涨跌幅、成交量/额、开高低收、市值、PB、换手率、量比、交易状态等，并有市场缓存。这是当前最低成本的盘中覆盖。
- `src/jqdata.ts` 与 Tauri 命令已支持用户配置 JQData 账号、连接测试、通用查询、历史/日线和最新价缓存；项目能力目录还包含股票、基金、指数、期货、财务、宏观、因子与风险模型。JQData 当前更适合盘后研究和历史回放，不应承担高频 UI 刷新。
- `src/research.ts` 已存在 `sample | jqdata | eastmoney` 来源标识和“实时覆盖样例、失败保留样例”的合并逻辑，可自然扩展为 `futu`，但每个组件仍应展示来源、采集时间和延迟状态。

## 2. 覆盖矩阵

| 工作台模块 | 东方财富现有接口 | 聚宽 JQData | 富途 OpenD | 推荐主源 / 降级 |
|---|---|---|---|---|
| 指数卡片、股票快照、涨跌榜、全部股票 | 强：当前已实现全市场批量快照 | 中：可取价格，但更适合研究/低频 | 强：订阅/快照 API，受账户行情权限与频率限制 | 富途授权用户用 OpenD；否则东财；最后缓存 |
| 分时、K 线、逐笔、盘口 | 中-强：当前已有分笔，K 线可继续走网页端接口 | 强历史、弱实时交互 | 强：订阅推送、K 线、逐笔、摆盘等，但不同市场/权限可用性不同 | OpenD → 东财 → 最后成功快照 |
| 热力图、涨跌分布、热门榜 | 强原料：用全市场快照本地聚合 | 中：适合盘后计算 | 强原料：快照/订阅后本地聚合 | 本地统一计算；OpenD/东财只负责原始行情 |
| 行业/概念板块、板块成分 | 中-强：网页接口常见但字段/协议稳定性弱 | 强：行业分类与成分适合研究 | 强：板块列表、所属板块、板块成分有正式 API | OpenD 或 JQData 做标准分类；东财仅降级，并保存 vendor taxonomy |
| 资金流、异动/智能盯盘 | 中：网页端可得但非正式开发者契约 | 中：可做日频因子/统计 | 中-强：有资金流等行情能力；异动规则宜本地计算 | OpenD 原料 + 本地规则；缺权限时东财快照本地计算 |
| 财报、估值、公司资料、分红 | 中：网页接口覆盖广但稳定性/授权不清 | 强：结构化财务、估值、公司与历史序列 | 中：提供部分财务/公司相关接口，覆盖需逐市场核验 | JQData 主源；OpenD/东财只补当前展示 |
| 宏观数据、财经日历 | 弱-中：网页内容可抓但不宜作结构化契约 | 强：宏观时间序列 | 弱-中：不是其最强项 | JQData → 官方统计源缓存；不可用时显示静态最近值 |
| 因子、风险模型、回测研究 | 弱 | 强：因子库、风险模型与历史研究是核心优势 | 弱 | JQData → 已缓存研究快照；不应由 OpenD 替代 |
| 财报日历、派息日历、新股日历 | 中：页面数据可用但协议风险 | 中-强：可由公司行动/财务数据构造 | 需逐项核验市场支持，不能默认 A 股全覆盖 | JQData/交易所公告聚合 → 东财页面降级 |

## 3. 富途 OpenD 的实际边界

- 架构：客户端 SDK 连接本机或局域网 OpenD，OpenD 负责登录、权限和行情连接，不是浏览器直接调用的无鉴权 REST 服务。官方总览：[Futu OpenAPI 文档](https://openapi.futunn.com/futu-api-doc/intro/intro.html)。
- 行情能力：官方文档列出实时报价、订阅推送、K 线、逐笔等接口；板块可通过板块列表/所属板块/板块成分接口获得。参考：[行情接口目录](https://openapi.futunn.com/futu-api-doc/quote/quote.html)、[获取股票报价](https://openapi.futunn.com/futu-api-doc/quote/get-stock-quote.html)、[获取板块成分](https://openapi.futunn.com/futu-api-doc/quote/get-plate-stock.html)、[获取所属板块](https://openapi.futunn.com/futu-api-doc/quote/get-owner-plate.html)。
- 权限与额度：可见行情等级取决于账户、市场和订阅权限；订阅数量、调用频率及历史 K 线请求有额度/频控。产品必须把 `no_permission`、`quota_exceeded`、`OpenD_offline` 设计为正常状态，而不是异常页面。参考：[行情权限与额度说明](https://openapi.futunn.com/futu-api-doc/intro/authority.html)。
- 授权建议：将 OpenD 作为“连接我的富途”本机数据适配器，原始行情不上传云端、不跨用户共享；商业化前应逐条确认富途服务条款、市场数据授权和展示/缓存/再分发限制。

## 4. 推荐分层与降级状态机

1. **盘中实时层**：若 OpenD 健康且当前证券具备权限，使用富途推送/快照；否则切到东方财富现有批量快照。两者都失败时使用本地最后成功缓存，并显示“截至 HH:mm:ss / 已延迟 N 分钟”。
2. **研究数据层**：财务、宏观、因子、历史截面优先 JQData；查询失败先读带 `as_of`、`fetched_at`、`source`、`schema_version` 的缓存，过期后只降级为只读，不伪装成实时。
3. **派生指标层**：涨跌分布、热力图、排行榜、市场宽度、智能盯盘统一在本地从同一批行情快照计算，避免不同组件各调一个源导致口径冲突。
4. **组件级而非整页降级**：每张卡片保存 `primary_source`、`fallback_source`、`freshness_sla`；某源缺少板块/资金流权限时只降级该卡片，指数与个股行情仍可正常更新。
5. **强制可见的数据可信度**：页头显示全局“实时/延迟/离线”，组件 tooltip 显示供应商、时间戳、是否复权与口径；同证券跨源切换时先做代码、币种、复权、成交量单位和涨跌停规则归一化。

## 5. 产品落地优先级

- **P0**：保留东财现有适配器；抽象统一 `MarketDataProvider`，加入健康检查、字段级 capability、缓存和 provenance，不先重写所有卡片。
- **P1**：新增可选 Futu OpenD 本机连接，只接指数/个股快照、订阅、K 线、逐笔、板块四类高价值能力；设置页展示 OpenD 地址、登录状态、行情权限和订阅配额。
- **P1**：JQData 专职财务、宏观、因子和历史研究；避免拿账号密码做高频轮询，延续当前缓存设计。
- **P2**：资金流、异动、财报/派息/财经日历逐模块做 capability probe；没有被官方文档和 A 股实测确认的功能，不在 UI 中声称“富途支持”。

## 来源与局限

- 聚宽官方入口：[JQData 数据说明/帮助](https://www.joinquant.com/help/api/help?name=JQData)。
- 东方财富当前能力结论来自本仓库实现；所调用 `push2` / `push2delay` 属网页行情接口，未发现本项目内对应的正式开发者授权契约，因此应视为**非官方兼容层**，需要监控字段漂移、限流和合规风险，不能宣称为稳定 SLA。
- 本文没有把富途 UI 截图中的“智能盯盘、走势预测”等成品能力直接等同于 OpenAPI 能力；其中多数应由 Alpha Studio 在授权行情原料之上自行计算。
