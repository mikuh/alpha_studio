# DeepSeek V4 Flash：火山方舟官方规格核验

核验日期：2026-08-09（Asia/Shanghai）

## 结论

`DeepSeek V4 Flash` 是火山方舟正式收录的模型系列，不是 Alpha Studio 自行杜撰的型号。火山方舟当前模型目录列出了两个版本化模型标识：

- `deepseek-v4-flash-260425`
- `deepseek-v4-flash-ga-260731`

两者在方舟模型目录中的长度规格相同：

| 项目 | 官方规格 |
| --- | ---: |
| 上下文窗口 | 1024k tokens（即 1,048,576） |
| 最大输入 | 1024k tokens（即 1,048,576） |
| 最大回答 | 384k tokens（默认 4k） |
| 最大思维链 | 128k tokens |
| 能力 | 深度思考、文本生成、工具调用 |

因此，将 Alpha Studio 中该模型按未知第三方模型统一兜底成 64k，并在 75%（约 48k）开始自动压缩，明显低估了真实窗口，足以解释截图中一次任务内反复压缩上下文的现象。对任一上述官方版本，传给 Codex 的 `model_context_window` 应使用 `1_048_576`，而不是 `65_536`。

方舟模型目录还显示：

- `deepseek-v4-flash-260425`：最大 RPM 15,000，最大 TPM 1,500,000。
- `deepseek-v4-flash-ga-260731`：最大 RPM 500，最大 TPM 1,000,000。
- 两个版本均列有 Responses API 与 Chat API；目录中的缓存能力栏列有 Responses API、前缀缓存和 Session 缓存（GA 条目页面当前重复显示了一次“前缀缓存”，不影响本次窗口结论）。

官方来源：[火山方舟模型列表](https://www.volcengine.com/docs/82379/1330310)

## 官方计费

火山方舟价格页使用通用计费模型名 `deepseek-v4-flash`，没有分别为两个日期版本列出不同价格。当前按 token 后付费价格为：

| 计费项 | 单价（人民币） |
| --- | ---: |
| 输入（非音频） | 1.00 元 / 百万 tokens |
| 输出 | 2.00 元 / 百万 tokens |
| 缓存命中（非音频） | 0.20 元 / 百万 tokens |
| 缓存存储 | 0.017 元 / 百万 tokens / 小时 |
| 输入或缓存命中（音频） | 不支持 |

官方价格页说明在线推理费用由输入、缓存命中、缓存存储和输出等计费项累加；以上数值来自该页 `deepseek-v4-flash` 行。不要采用火山开发者社区用户文章中出现的 `0.02 元 / 百万 tokens` 缓存价：它与当前方舟官方价格表的 `0.20` 不一致。

官方来源：[火山方舟模型价格](https://www.volcengine.com/docs/82379/1544106)

## 型号与调用标识边界

- UI 展示名“DeepSeek V4 Flash”本身可以对应方舟正式系列，但实际请求应保存并核对版本化 `upstream_model`，优先匹配 `deepseek-v4-flash-ga-260731` 或 `deepseek-v4-flash-260425`。
- 价格元数据应按通用计费名 `deepseek-v4-flash` 关联；官方价格页没有给出两个版本之间的价差，不能自行假设存在版本价格差。
- 两个官方版本的窗口完全相同，所以即使现有路由暂时只保存了展示名，只要能确认上游确属 DeepSeek V4 Flash，窗口修复值仍可确定为 `1_048_576`。
- 官方目录同时给出“上下文窗口 1024k”“最大输入 1024k”“最大回答 384k”。这几个是分别列出的能力上限，不应把最大回答简单从上下文窗口中扣除后再把较小结果冒充官方窗口。运行时自动压缩阈值可以额外留输出余量，但模型元数据本身应保存完整官方窗口。

## 与自托管文档的区别

火山引擎 VKE 还有一篇官方自托管部署文档，模型制品名为 `DeepSeek-V4-Flash-FP8`，SGLang 服务中的实际 `model` 示例为 `deepseek-v4-fp8`。该文档的示例接口把 `max_tokens` 参数限制为 1–8192、默认 4096，但这是该自托管模板接口的请求参数约束，不是方舟托管模型的 384k 最大回答规格，不能用它覆盖方舟模型目录。

官方来源：[通过 LLM 通用模板快速部署 DeepSeek-V4-Flash 模型](https://www.volcengine.com/docs/6460/2373771)

## 对 Alpha Studio 修复的直接建议

1. 对 `deepseek-v4-flash-260425`、`deepseek-v4-flash-ga-260731`，以及经路由核验确实指向该系列的 `deepseek-v4-flash`，写入 `context_window_tokens = 1_048_576`。
2. 不再对该模型套用 64k 自定义模型兜底；压缩阈值按 1024k 窗口计算，并为输出留运行时余量。
3. 模型价格元数据写入输入 1.00、输出 2.00、缓存命中 0.20（单位均为元/百万 tokens）；缓存存储若当前计费链路不支持，可单独保留而不要误并入输入价。
4. 管理端应显示版本化 `upstream_model`。如果当前只保存了 UI 标签，需在发布配置中补齐真实上游 ID，避免未来不同版本窗口或限流变化时无法精确迁移。
