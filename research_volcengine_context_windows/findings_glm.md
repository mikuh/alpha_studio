# GLM-5.2 火山方舟官方核验结果

核验时间：2026-08-09（只使用火山引擎/火山方舟官方文档）

## 结论

- 火山方舟当前确实存在 GLM-5.2，正式版本模型标识为 `glm-5-2-260617`；模型详情链接使用系列 ID `glm-5-2`，价格表中的商品名称写作 `glm-5.2`。因此 Alpha Studio 界面的“GLM-5.2”不是凭空命名，但本地路由的 `upstream_model` 仍应核对并固定为官方 API 版本标识 `glm-5-2-260617`，避免把展示名误当请求模型名。
- 上下文窗口：`1024k` token（运行时按二进制 k 展开为 `1,048,576`）。
- 最大输入：`1024k` token（`1,048,576`）。
- 最大回答：`128k` token（`131,072`，默认 4k）。
- 最大思维链：`128k` token（`131,072`）。
- 模型能力包含深度思考、文本生成、工具调用，并支持 Responses API 与 Chat API。
- 在线常规推理价格：输入 `8.00 元/百万 token`，缓存命中 `2.00 元/百万 token`，缓存存储 `0.017 元/百万 token/小时`，输出 `28.00 元/百万 token`；价格表未对 GLM-5.2 设置长度分档条件。

## 对当前故障的直接含义

此前把非 GPT 模型统一按 `64k` 处理，与官方的 `1024k` 相差 16 倍，会让 Codex 在远未接近真实模型窗口时反复压缩上下文。

如果 Alpha Studio 仍为每次运行设置固定 `5 元`安全预算，单看 GLM-5.2 的非缓存输入：

- `5 / 8 × 1,000,000 = 625,000 token`，也就是输入超过约 `625k` 后，尚未计算任何输出费用，5 元上限就已不够。
- 官方允许的 `1024k` 最大输入对应 `1,048,576 / 1,000,000 × 8 = 8.388608 元`输入费。
- 官方允许的 `128k` 最大回答对应最多 `131,072 / 1,000,000 × 28 = 3.670016 元`输出费。

因此固定 5 元上限与官方规格不相容；即使模型仍有输入空间，网关也可能先以 `per-run safety limit is too small for the request input` 拒绝。修复应按模型价格和实际/允许 token 数动态生成运行安全预算，而不能只调整压缩阈值。

## 证据

1. [火山方舟《模型列表》](https://www.volcengine.com/docs/82379/1330310)（文档接口显示更新时间 2026-08-07）：GLM 行明确列出 `glm-5-2-260617`、上下文窗口 1024k、最大输入 1024k、最大回答 128k、最大思维链 128k；同页还列出其 Responses API / Chat API 支持。
2. [火山方舟《模型价格》](https://www.volcengine.com/docs/82379/1544106)（文档接口显示更新时间 2026-08-07）：在线推理表的 `glm-5.2` 行给出输入 8.00、缓存存储 0.017、缓存命中 2.00、输出 28.00，单位均见表头。

## 型号歧义说明

- 官方文档同时出现三种写法，语义不同：
  - `glm-5-2-260617`：带日期的正式版本模型标识，最适合写入 `upstream_model`。
  - `glm-5-2`：控制台模型系列/详情 ID。
  - `glm-5.2`：价格表商品名称。
- 仅凭界面展示名“GLM-5.2”不能证明网关实际发送了哪个标识；需要在本地路由配置中核对 `upstream_model`。但“火山方舟没有 GLM-5.2、实际只能是 GLM-4.7”的假设已被当前官方模型列表否定。GLM-4.7 是另一个旧型号，官方标为 `glm-4-7-251222`，窗口仅 200k 且已标注“即将下线”，不应拿它的窗口代替 GLM-5.2。
