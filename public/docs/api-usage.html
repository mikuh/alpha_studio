Alpha Studio 模型网关 API

受鉴权、单次消费上限和按真实用量结算保护的 Responses API

🔐 所有模型请求都必须鉴权
网关不接受匿名调用或长期静态 API Key。桌面端使用设备 Bearer token 创建运行，再以短期、单次、模型绑定的 run token 调用模型。

快速开始

1. 创建单次运行

  1. 使用公司名和授权码激活 Alpha Studio 桌面端，取得设备 token。
  2. 客户端携带设备 token 调用 POST /api/runs/create。
  3. 服务端确认账户余额大于 0 后创建运行，不冻结余额，并返回 20 分钟有效的 run token。
  4. run token 只能真正发起一次上游推理，且不能切换模型。
⚠️ 重要提示
不要记录、转发或复用 run token。过期、伪造、已消费的 token，以及被撤销设备签发的 token 都会被拒绝。

2. API 端点

http://localhost:8080/v1

或您的服务器地址：https://your-domain.com/v1

3. 认证方式

在请求头中添加 Authorization 字段：

Authorization: Bearer YOUR_SHORT_LIVED_RUN_TOKEN

调用约束

  • 请求体使用 OpenAI Responses 格式，不提供 /v1/chat/completions 或图像生成端点。
  • 服务端会根据不占用余额的单次消费上限收紧 max_output_tokens。
  • 请求中的模型名不能覆盖 run token 已绑定的模型。

curl 示例

Responses 请求

curl -X POST http://localhost:8080/v1/responses \
  -H "Authorization: Bearer YOUR_SHORT_LIVED_RUN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_BOUND_MODEL",
    "input": "你好！",
    "max_output_tokens": 800,
    "stream": false
  }'

流式请求

curl -X POST http://localhost:8080/v1/responses \
  -H "Authorization: Bearer YOUR_SHORT_LIVED_RUN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "YOUR_BOUND_MODEL",
    "input": "讲个笑话",
    "max_output_tokens": 800,
    "stream": true
  }'

可用端点

端点 方法 描述
/v1/models GET 获取可用模型列表
/v1/responses POST Responses 接口（支持流式和非流式）
/api/runs/create POST 使用设备 token 检查正余额并创建单次运行

请求参数

Responses

参数 类型 必填 说明
model string 是 模型名称
input string / array 是 输入内容
max_output_tokens int 否 最大生成 token 数；服务端可能按单次消费安全上限下调
stream boolean 否 是否流式输出（默认 false）

错误处理

状态码 原因 解决方法
401 Bearer token 缺失、伪造或已过期 重新激活设备或创建新的运行
403 余额不足、设备无权访问或 run token 已消费 检查设备状态、余额，并创建新的运行
400 请求参数错误 检查请求格式和参数
502 上游模型服务失败 检查供应商状态；账单中确认是否有用量待核对记录

安全建议

  • 不要将设备 token 或 run token 写入日志、仓库或分析系统。
  • run token 是短期单次凭据，不要实现客户端复用。
  • 授权码只在创建时返回明文；数据库仅保存哈希和末四位提示。
  • 上游缺失 usage、超时、流中断或可能已产生费用的错误会标记为 usage_unavailable；系统只扣除已确认的 Token 用量，不使用单次上限猜测扣费。
